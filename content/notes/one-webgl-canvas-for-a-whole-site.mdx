This site draws WebGL in several places:

- The dust portrait on the home page.
- The experiment previews.
- The live demos in the registry.

Almost all of it renders through one `<Canvas>`. The exception is at the end.

## One canvas, many views

The root layout mounts `components/scene/shared-canvas.tsx` once. The canvas is fixed, covers the viewport and sits at z-30. A component that wants 3D does not create a canvas. It registers a slot with `useViewSlot`, passing a ref to a DOM element and the scene to draw there:

```tsx
useViewSlot("stage", stageRef, <Stage />);
```

The canvas renders each registered slot as a drei `View`. A `View` reads the position of its DOM element and draws its scene inside that rectangle:

```tsx
return slots.map((slot) => (
  <View index={slot.priority} key={slot.id} track={slot.track}>
    <Suspense fallback={null}>{slot.node}</Suspense>
  </View>
));
```

A WebGL scene here never creates its own `Canvas`.

## It only runs when it has work

- A view mounts only when its element is near the viewport.
- With no views near the viewport, the canvas renders on demand.
- Reduced motion pauses the loops.
- Without WebGL, a static fallback takes the place of the view.

## When I did not use it

Slime is a WebGPU experiment, and a WebGPU renderer cannot draw into the shared WebGL context. It owns a second canvas through `GpuStage`, which mounts the canvas only while the stage is in view and lets three fall back to WebGL2. It is the only second canvas on the site.
