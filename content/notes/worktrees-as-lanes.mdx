Two agents in one checkout edit the same files and fight over the branch. So every task or issue I hand out gets its own git worktree and its own branch. I call each one a lane.

## One task, one worktree, one branch

A worktree is a second working directory backed by the same repository. Conductor creates one for every workspace. When Claude Code spawns subagents in this repo, each one runs in `.claude/worktrees/agent-*`.

```bash
git worktree add .claude/worktrees/agent-hero -b agent/hero main
cd .claude/worktrees/agent-hero
bun install --frozen-lockfile
```

The lane owns its files, its branch and its build output. The git objects and the remotes stay shared.

## Disjoint scopes keep merges small

A lead agent merges each lane back. The conflicts stay small because I cut lanes along files: every agent gets a scope it owns. In the portfolio redesign the only conflicts were of two kinds:

- A route-dates JSON file that gets regenerated after the merge anyway.
- An experiments registry where two agents appended entries to the same list.

Both took one edit to resolve. When two lanes need the same file, one of them owns it and the other asks.

## Two gotchas

<Callout tone="warning" title="A new worktree may have no node_modules">
  Run `bun install --frozen-lockfile` before the first typecheck or test.
</Callout>

Some files derive from git history. In this repo `lib/site/route-dates.json` holds the last commit date of every route. A lane cannot know the date of a merge that has not happened yet, so the lead regenerates that file after the merge commit:

```bash
bun run seo:dates
```

Then it commits the dates on their own.
