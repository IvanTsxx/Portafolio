title: Why the fields stay ASCII
date: "2026-07-28"
excerpt: Generative density belongs in a character grid. The site cosmos is WebGL; Lab fields stay on pre + rAF. SVG stays for static marks.
---

The portfolio identity is a generative terminal surface. That contract splits into two live paths — and one static path.

## Site cosmos → WebGL

Every route floats over a persistent `AsciiWorld` canvas. Wormhole travel, land moods, and click ripples need one shared field that survives navigation. That is WebGL on purpose — not a Lab panel scaled up.

## Lab / dissolve → `<pre>` + rAF

Seeded math written into a monospace grid at rAF. That is why exploratory fields stay ASCII `<pre>`, not SVG paths.

### What ASCII wins here

- **O(cells) buffers** map cleanly to `textContent` mutation — zero React re-renders per frame.
- **Character ramps** encode density with typographic texture that reads as system, not illustration.
- **SSR snapshot + reduced-motion** freeze share the same string pipeline.
- **Brand test:** replace a Lab field with a soft SVG blob and that panel could belong to anyone.

## Where SVG still belongs

Static marks: Bayer dither tiles, icons, and fixed chrome ornaments. Those do not need per-frame density evaluation.

<Callout tone="signal" title="Rule">
Site background → WebGL cosmos. Live Lab density → ASCII engine. Fixed geometry → SVG / CSS. Do not redraw generative panels as path art.
</Callout>

```ts
// Lab / dissolve fields
pre.textContent = frame

// Site shell (PortalProvider)
// AsciiWorld — shared WebGL canvas

// Static ornament
// dither-bg utility, lucide / SVGL icons
```

---

The `<pre>` engine cap stays at **9000 cells**. Promote a Lab field to Canvas only after profiling proves the text path is the bottleneck — and document it in `docs/ascii-engine.md`.
