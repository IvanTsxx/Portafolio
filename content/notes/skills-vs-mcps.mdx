I extend my agents in three ways: skills, MCP servers and command-line tools. Each one solves a different problem, so I pick by the problem.

## A skill teaches a procedure

A skill is a folder with a `SKILL.md` file. The agent loads it only when the task matches its description.

```md title=".claude/skills/ui-states/SKILL.md"
---
name: ui-states
description: Use when writing or reviewing UI code.
---

1. List the states before writing code.
2. Style each state with a data attribute.
```

I use skills for animation craft, Figma-to-code, shadcn, Tailwind design systems and design polish. None of them gives the agent new data. They change how it works.

## An MCP server gives access

An MCP server connects the agent to a system it cannot reach alone. The ones I use:

- Figma, for frames, variables and assets.
- Sanity, for schemas and documents.
- Notion and Linear, for notes and issues.
- context7, for current library docs.
- CodeGraph, for symbol source and call paths.

## Command-line tools fill the gaps

Some jobs need neither. A plain CLI works from any shell:

- `jg` (jevgrep) answers where and how something works.
- `codegraph explore` prints a symbol's source and its call paths.
- `rtk` runs shell commands through a proxy that trims their output to save tokens.

## How I decide

| The agent needs                    | I reach for      |
| ---------------------------------- | ---------------- |
| A procedure it keeps getting wrong | A skill          |
| Data that lives in another system  | An MCP server    |
| A fast answer about the code       | A CLI tool       |
| To stop repeating the same mistake | A test or a lint |

<Callout tone="tip" title="Rule of thumb">
  The second time I correct the same mistake, I write a test or a lint rule
  instead of another paragraph of instructions.
</Callout>
