# Agent Workshop

Ivo's portfolio. A paper-and-ink technical document built around his GitHub profile, with small procedural 3D agents working across the page, all rendered through one shared canvas.

Next.js 16 (App Router), React 19, TypeScript strict, Tailwind v4, shadcn (Base UI), GSAP + ScrollTrigger, React Three Fiber + Drei, MDX, zod, Bun.

## Scripts

```bash
bun install
bun dev                 # http://localhost:3000
bun run typecheck       # next typegen + tsc
bun x oxlint            # ultracite lint
bun x ultracite fix     # format + autofix
bun test                # unit tests (content, registry)
bun run build           # shadcn build (public/r) + next build
```

## Where things live

- Identity, links, routes, registry URL: `lib/site/config.ts`. The site calls him `nickname` ("Ivo"). The legal `name` renders once, in the dossier.
- Global search palette (`⌘K`, `Ctrl+K`, `/`): the server builds the index in `lib/search/build-index.ts` from the content, lab, registry and config loaders, `lib/search/match.ts` matches and returns highlight ranges, and `components/command/**` renders it. A new route, section, note, experiment or registry item shows up without touching the palette, except a new home section, which is listed in `homeSections` in `lib/site/config.ts`.
- Header stars chip: `lib/site/github-repo.ts` reads `stargazers_count` for `siteConfig.repository` hourly and hides the count when GitHub does not answer.
- Design tokens and utilities (`label`, `display`, `blueprint-grid`, `grain`): `app/globals.css`. Direction notes: `docs/direction.md`.
- Agent roles and scenes: `lib/agents/roles.ts`, `lib/agents/scenes.ts`.
- Character rig, actions, materials, accessory kits: `components/agents/**`. Notes: `docs/characters.md`.
- Shared canvas: `components/scene/scene-layer.tsx` is mounted once in the root layout and loads three.js only when a slot appears. Mark companion stops with `<AgentWaypoint role action side />` inside a `relative` section, and scenes with `<AgentScene scene label />` (`debugging`, `figma-to-code`, `feature`, `code-search`).
- GitHub data: `lib/github/profile.ts` reads `GITHUB_TOKEN` from `.env.local`, revalidates hourly, and falls back to `lib/github/snapshot.json` (refresh with `bun lib/github/write-snapshot.ts`). `lib/github/privacy.ts` strips anything matching basement before render.
- How I work and stack copy: `lib/site/practice.ts`.

## Adding content

- **Case study.** Add `content/notes/<slug>.mdx` starting with `export const meta = { kind: "case-study", ... }`. The schema is `caseStudyMetaSchema` in `lib/content/schema.ts`; the filename is the slug. Set `sample: false` when it is real so it gets indexed and loses the sample label.
- **Note.** Add `content/notes/<slug>.mdx` with `meta` matching `fieldNoteMetaSchema` (`kind: "note"`). MDX blocks (`Callout`, `Figure`, `Video`, `Table`, `Diagram`, `Demo`, `Steps`, `NoteList`) are available without imports. Write text-only children of JSX blocks as `{"text"}` so the formatter cannot split them into paragraphs.
- **Experiment.** Add a folder in `components/lab/experiments/<slug>/` with `poster.tsx`, `preview.tsx` and, for client experiments, a `live.tsx` that dynamic-imports the preview. Then add one entry in `lib/lab/experiments.ts` and its slug to `ExperimentSlug`.
- **Registry item.** Add the item to `registry.json`, the source under `registry/ivan/`, an example in `registry/ivan/examples/<name>/` and a demo in `components/registry-docs/demos/<name>.tsx`. `bun test` fails if a piece is missing or if the item depends on a site-only token it does not ship.
- **Agent role.** Add the role to `lib/agents/roles.ts`, write an accessory module in `components/agents/accessories/` and register it. The type system fails the build until the kit exists.

## Registry

Install from a deployed site:

```bash
bunx --bun shadcn@latest add https://bongi.dev/r/technical-grid.json
```

Or register the namespace in `components.json` with `"@ivan": "https://bongi.dev/r/{name}.json"` and run `bunx --bun shadcn@latest add @ivan/technical-grid`.

## Sample content

Work entries and posts ship with `sample: true`. They render a visible "Sample content" label, are `noindex`, and stay out of the sitemap until flipped.
