# Agent Workshop

Ivan Bongiovanni's portfolio. A dark, techno-industrial site where small procedural 3D agents research, architect, build, debug and ship, while the engineer designs the system and owns the decisions.

Next.js 16 (App Router), React 19, TypeScript strict, Tailwind v4, shadcn (Base UI), GSAP + ScrollTrigger, React Three Fiber + Drei, MDX, zod, Bun.

## Scripts

```bash
bun install
bun dev                 # http://localhost:3000
bun run typecheck       # next typegen + tsc
bun x oxlint            # ultracite lint
bun x ultracite fix     # format + autofix
bun test                # unit tests (content, registry)
bun run build           # shadcn build (public/r) + next build
```

| --- | --- |
| `/` | `app/page.tsx`, `components/home/**`, `lib/home/**` |

| `/lab`, `/lab/[slug]` | `lib/lab/experiments.ts`, `components/lab/experiments/**` |

## Where things live

- Identity, links, routes, registry URL: `lib/site/config.ts`.
- Design tokens and utilities (`label`, `display`, `blueprint-grid`, `grain`): `app/globals.css`. Direction notes: `docs/direction.md`.
- Agent roles and the workflow stages: `lib/agents/roles.ts`, `lib/agents/workflow.ts`.
- Character rig, actions, materials, accessory kits: `components/agents/**`. Stage and lazy loading: `components/scene/**`. Notes: `docs/characters.md`.

## Adding content

- **Project.** Add `content/work/<slug>.mdx` starting with `export const meta = { ... }`. The schema is `workMetaSchema` in `lib/content/schema.ts`; the filename is the slug. Set `sample: false` when it is real so it gets indexed and loses the sample label. `featured: true` puts it first on the home page.
- **Post.** Add `content/blog/<slug>.mdx` with `meta` matching `blogMetaSchema`. MDX blocks (`Callout`, `Figure`, `Video`, `Table`, `Diagram`, `Demo`, `Steps`, `NoteList`) are available without imports. Write text-only children of JSX blocks as `{"text"}` so the formatter cannot split them into paragraphs.
- **Experiment.** Add a folder in `components/lab/experiments/<slug>/` with `poster.tsx`, `preview.tsx` and, for client experiments, a `live.tsx` that dynamic-imports the preview. Then add one entry in `lib/lab/experiments.ts` and its slug to `ExperimentSlug`.
- **Registry item.** Add the item to `registry.json`, the source under `registry/ivan/`, an example in `registry/ivan/examples/<name>/` and a demo in `components/registry-docs/demos/<name>.tsx`. `bun test` fails if a piece is missing or if the item depends on a site-only token it does not ship.
- **Agent role.** Add the role to `lib/agents/roles.ts`, write an accessory module in `components/agents/accessories/` and register it. The type system fails the build until the kit exists.

## Registry

Install from a deployed site:

```bash
bunx --bun shadcn@latest add https://bongi.dev/r/technical-grid.json
```

Or register the namespace in `components.json` with `"@ivan": "https://bongi.dev/r/{name}.json"` and run `bunx --bun shadcn@latest add @ivan/technical-grid`.

## Sample content

Work entries and posts ship with `sample: true`. They render a visible "Sample content" label, are `noindex`, and stay out of the sitemap until flipped.
