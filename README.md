# Ivo's portfolio

Ivo's portfolio: a quiet, monochrome observatory for selected work, writing and a lab of installable creative-code experiments. 3D and shaders render through one shared canvas, except the WebGPU slime, which owns its own. Live at [bongi.dev](https://bongi.dev).

Next.js 16.4 (App Router, Cache Components, Partial Prefetching), React 19, TypeScript strict, Tailwind v4, shadcn (Base UI), React Three Fiber + Drei, MDX, zod, Upstash Redis, Bun. There is no animation library: UI motion is CSS.

## What is on the site

- **Home.** The Gallery layout (`components/home/layouts/gallery-layout.tsx`): a sticky plate with the dust portrait, a sky caption (Tucumán time, tonight's moon), the Spotify now-playing card and social icons, beside the statement, leader rows for Work, Lab, Writing and Skills, and a grid of the newest Lab posters. Work has no page of its own.
- **Lab.** Eight experiments at `/experiments`: dust-portrait, lunar-dither, orbit-dust, signal-tear, slime (WebGPU), speed-smear, super-saiyan and vegeta. Each takes anonymous reactions.
- **Detail levels.** Plain, Guides and Measure change how much of the working drawing shows. Press `D` to cycle, or use the footer control.
- **Page peel.** Drag or tap the bottom-right corner to peel the page back to the underside, a working drawing of the site. The footer has a keyboard trigger.
- **Writing, Skills, Registry, System.** Notes and case studies, installable Agent Skills, shadcn registry items and the generated design system.

## Scripts


## Skills

Agent Skills live in `skills/<name>/SKILL.md`. Install them with the [skills CLI](https://github.com/vercel-labs/skills):

```bash
npx skills add IvanTsxx/Portafolio --skill frontend-care
npx skills add IvanTsxx/Portafolio --skill frontend-care -g   # global
npx skills add IvanTsxx/Portafolio --list                     # see what is available
```

| Skill | What it does |
| --- | --- |
| [`frontend-care`](skills/frontend-care/) | Care-first UI checklist: states, focus, hit areas, numbers, hostile paths. Any framework. |
| [`shared-canvas`](skills/shared-canvas/) | One fixed WebGL canvas for a whole site: the slot registry, the canvas, a consumer and a checklist. |

## Registry

Items: `magnetic-button`, `dither-image`, `page-peel`, `lunar-dither`, `orbit-dust`, `signal-tear`, `speed-smear`, `storm-print`, `blast-print`, `dust-portrait` and `slime`. Install components from the deployed site:

```bash
bunx --bun shadcn@latest add https://bongi.dev/r/dither-image.json
```

Or register the namespace in `components.json` with `"@ivan": "https://bongi.dev/r/{name}.json"` and run `bunx --bun shadcn@latest add @ivan/dither-image`.

## Where things live

- Identity, links, routes and home sections: `lib/site/config.ts`. The site calls him `nickname` ("Ivo"). The legal `name` is read once, by the home signature (`components/site/signature.tsx`), which prints the first name.
- Search palette (`⌘K`, `Ctrl+K`, `/`): `lib/search/build-index.ts` builds the index from the notes, experiments, registry, skills and config loaders. `components/command/**` renders it. New items show up without touching the palette.
- Tokens and utilities: `app/globals.css` and `lib/design-system/`. Direction: `docs/direction.md`. Generated design spec: `docs/design.md`.
- Brand marks: `components/site/monogram.tsx` draws the monogram from `lib/site/monogram.ts`. `app/icon.svg` follows the browser's light or dark scheme, `app/favicon.ico` is generated by `bun run brand:favicon`, and `app/apple-icon.tsx` and `app/pwa-icon/[size]` come from `lib/site/icon-mark.tsx`. Social images are the `opengraph-image.tsx` files over `lib/content/og-image.tsx`.
- Shared canvas: `components/scene/scene-layer.tsx` mounts once in the root layout and loads three.js only when a slot appears. WebGPU experiments own their Canvas through `registry/ivan/components/gpu-stage/gpu-stage.tsx`.
- Page peel and underside: `app/layout.tsx` wraps the site in `PagePeel` (`registry/ivan/components/page-peel/`). The underside is `components/underside/underside.tsx`, fed by `lib/site/revision.ts` (git SHA and recent commits injected by `next.config.ts`). Detail levels live in `components/site/detail-control.tsx`.
- Reactions: `lib/reactions/store.ts` uses Upstash Redis in production and a JSON file in `.data/` in development. Kinds are in `lib/reactions/kinds.ts`.
- Now playing: `components/home/now-playing.tsx` polls `/api/now-playing`. See Environment variables for the Spotify setup.
- GitHub data: `lib/github/profile.ts` reads `GITHUB_TOKEN` from `.env.local` and falls back to `lib/github/snapshot.json` (refresh with `bun lib/github/write-snapshot.ts`). The site uses it for the avatar. `lib/github/privacy.ts` strips anything matching basement before render.
- Work rows and skills: `lib/site/experience.ts` and `lib/site/capabilities.ts`.
- Analytics and search engines: `<Analytics />` from `@vercel/analytics` in the root layout. Google Search Console verifies `bongi.dev` through DNS. `app/sitemap.ts` and `app/robots.ts` feed the crawlers.

## Environment variables

Put them in `.env.local` for development and in the Vercel project for production. Every one is optional: the site degrades without it.

| Variable | Used by | Without it |
| --- | --- | --- |
| `GITHUB_TOKEN` | `lib/github/profile.ts`, `lib/github/write-snapshot.ts` | the avatar and profile come from `lib/github/snapshot.json` |
| `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`, `SPOTIFY_REFRESH_TOKEN` | `lib/spotify/now-playing.ts` | `/api/now-playing` answers 503 and the card hides |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` (or `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`) | `lib/reactions/store.ts` | development writes `.data/reactions.json`; production hides the reaction bar |

To mint `SPOTIFY_REFRESH_TOKEN`, create a Spotify app with the redirect URI `http://[::1]:3000/api/spotify/callback`, set the client id and secret, run `bun dev`, open `/api/spotify/login` and copy the line `/api/spotify/callback` prints. Both routes answer 404 outside development.

## Adding content

`AGENTS.md` holds the step-by-step routines. In short:

- **Note or case study.** Add `content/notes/<slug>.mdx` with `export const meta = {…}` matching `lib/content/schema.ts`. Set `sample: false` when it is real.
- **Experiment.** Copy the folder pattern of `components/lab/experiments/lunar-dither/`, add its light and dark posters to `public/lab/posters/`, and register it in `lib/lab/experiments.ts`.
- **Registry item.** Source in `registry/ivan/`, entry in `registry.json`, demo in `components/registry-docs/demos/<name>.tsx`, then `bun run registry:build`.
- **Skill.** Add `skills/<name>/SKILL.md` with `name` (equal to the folder) and `description` frontmatter. The site, search, sitemap and `llms.txt` pick it up.

## Sample content

Placeholder notes ship with `sample: true`. They render a visible "Sample content" label, are `noindex`, and stay out of the sitemap until flipped.
