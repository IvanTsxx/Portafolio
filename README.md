# Ivo's portfolio

A paper-and-ink technical dossier built around Ivo's GitHub profile, with one small orange 3D companion that walks the page, all rendered through one shared canvas. Live at [bongi.dev](https://bongi.dev).

Next.js 16.4 (App Router, Cache Components, Partial Prefetching), React 19, TypeScript strict, Tailwind v4, shadcn (Base UI), GSAP + ScrollTrigger, React Three Fiber + Drei, MDX, zod, Bun.

## Scripts

```bash
bun install
bun dev                 # http://localhost:3000
bun run typecheck       # next typegen + tsc
bun x oxlint            # lint
bun x ultracite fix     # format + autofix
bun test                # unit tests
bun run build           # shadcn build (public/r) + next build
bun run seo:check       # checks the build output, run after build
bun run seo:dates       # refresh lib/site/route-dates.json after a content commit
bun run design:md       # regenerate docs/design.md
```

## Registry

Install components from the deployed site:

```bash
bunx --bun shadcn@latest add https://bongi.dev/r/dither-image.json
```

Or register the namespace in `components.json` with `"@ivan": "https://bongi.dev/r/{name}.json"` and run `bunx --bun shadcn@latest add @ivan/dither-image`.

## Where things live

- Identity, links, routes and home sections: `lib/site/config.ts`. The site calls him `nickname` ("Ivo"). The legal `name` renders once, in the home intro.
- Search palette (`⌘K`, `Ctrl+K`, `/`): `lib/search/build-index.ts` builds the index from the notes, experiments, registry, skills and config loaders. `components/command/**` renders it. New items show up without touching the palette.
- Header stars chip: `lib/site/github-repo.ts` reads `stargazers_count` for `siteConfig.repository` through a `"use cache"` function and hides the count when GitHub does not answer.
- Tokens and utilities: `app/globals.css` and `lib/design-system/`. Direction: `docs/direction.md`. Generated design spec: `docs/design.md`.
- Companion rig, actions and accessory kits: `components/agents/**`. Notes: `docs/characters.md`.
- Shared canvas: `components/scene/scene-layer.tsx` mounts once in the root layout and loads three.js only when a slot appears. The companion picks its role from the route (`lib/site/companion-roles.ts`).
- GitHub data: `lib/github/profile.ts` reads `GITHUB_TOKEN` from `.env.local` and falls back to `lib/github/snapshot.json` (refresh with `bun lib/github/write-snapshot.ts`). `lib/github/privacy.ts` strips anything matching basement before render.
- How I work and stack copy: `lib/site/practice.ts`.
- Analytics and search engines: `<Analytics />` from `@vercel/analytics` in the root layout. Google Search Console verifies `bongi.dev` through DNS. `app/sitemap.ts` and `app/robots.ts` feed the crawlers.

## Adding content

`AGENTS.md` holds the step-by-step routines. In short:

- **Note or case study.** Add `content/notes/<slug>.mdx` with `export const meta = {…}` matching `lib/content/schema.ts`. Set `sample: false` when it is real.
- **Experiment.** Copy the folder pattern of `components/lab/experiments/dot-grid/` and register it in `lib/lab/experiments.ts`.
- **Registry item.** Source in `registry/ivan/`, entry in `registry.json`, demo in `components/registry-docs/demos/<name>.tsx`, then `bun run registry:build`.
- **Skill.** Add `skills/<name>/SKILL.md` with `name` (equal to the folder) and `description` frontmatter. The site, search, sitemap and `llms.txt` pick it up.

## Sample content

Placeholder notes ship with `sample: true`. They render a visible "Sample content" label, are `noindex`, and stay out of the sitemap until flipped.
