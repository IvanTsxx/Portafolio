# Predictability is a Feature

> A good UI is predictable. The user shouldn't have to think about what to do or what happens next. Predictability removes uncertainty.

A good interface answers, without the user having to think:
- Where do I click?
- What will happen?
- What changed?
- What do I do now?

## Mostly subconscious
"A lot of polish is just removing uncertainty." When expectations match behavior, the experience feels natural.

## Expectations come from other products
Users already know patterns from their OS, browser, and daily apps. Don't reinvent known interactions. Originality is for the design — not for how basic things work.

## The interface is a contract
Every interactive element makes a promise: a button runs an action, a link navigates, a checkbox toggles state. Break the promise and you lose trust.

## Menus are a stress test
Expected: hover highlights; `Enter` runs the selected option; arrows navigate; `Esc` closes.

## Don't invent new rules
`Enter` confirms · `Esc` closes · `Shift+Click` selects a range · `Cmd/Ctrl+K` opens the command palette. Changing these only creates doubt.

## Hotkeys
Shortcuts build muscle memory. Keep standards; if one changes, make it very clear.

## Domain vs interaction complexity
- ✅ **Domain complexity** is normal (Blender, Figma, After Effects) — learning the tool is part of the product.
- ❌ **Interaction complexity** should never exist — navigating, opening a menu, confirming, or closing a modal must feel familiar.

## Think ahead of the user
A good UI anticipates needs and helps without taking away control.
